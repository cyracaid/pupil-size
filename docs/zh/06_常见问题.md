# 06 · 常见问题（中文）

**Q1. 为什么同一个被试每一行的 `ValidSamples_validPercent` 都一样？**
因为它不是按段算的。它是这只眼**整段记录**通过伪影滤波的比例，每行重复。要看“这一段缺多少”，用 `SmoothSig_missingDataPercent`。

**Q2. 明明有眨眼，为什么这一段的均值看着很正常？**
`SmoothSig_*` 算在插值后的信号上。250 ms 以内的缺口被线性插值填平，均值里看不出任何痕迹；只有超过 250 ms 的才重新标成 NaN。两个段均值相同，底下的数据可能完全不同——均值一定要和 `SmoothSig_missingDataPercent`、`ValidSamples_sampleCount` 一起看。

**Q3. 为什么单位是像素，Range filter 也不是 1.5–9？**
MRC 日志存的是相机像素下的椭圆参数，不是毫米。论文默认的 1.5–9 是按毫米写的，直接套会把所有样本都剔掉。`example_kret_pipeline.m` 用数据自己定范围（有效瞳孔的 0.5–99.5 百分位 × 0.8 / 1.2），并在运行时打印出来。这些直径**不能**和文献里的毫米值直接比。

**Q4. 为什么 `outcome` 有时是 `O`？`actual_outcome` 是干什么的？**
两个“结果不确定”的条件，cue 时不可能知道是威胁还是安全，所以整个 trial 的 `outcome` 都是 `O`。`actual_outcome` 从 `Outcome` 那个 marker 读（`OutcomePTUOT` 还是 `OutcomePTUOS`），给出 `T` / `S`。要分威胁/安全就按 `actual_outcome` 分组；要问“被试当时知不知道”，用 `certainty`。

**Q5. 为什么是 84 个 trial、只有 24 个评分？**
4 run × 21 trial，而任务只在其中 24 个 trial 上要求评分。其余 trial 没有 `RatingStart`，这是设计，不是缺失。宽表里表现为 `has_rating = false`、`rating_s = NaN`。

**Q6. 为什么没有事件的文件也能生成 CSV？**
`trk2csv` 给什么转什么，并记一条 `NO_EVENTS`；`run` / `trial` / `phase` / `event` 留空。九个被试里有三个是这样，它们在事件表那一步被跳过，在 `05_all_markers_summary.csv` 里标成 `skipped_no_events`。不会为了凑数编任何东西。

**Q7. 能不能只重跑一个被试、不动别人？**
`ymtcEventTableBatch('Subjects', "sub149")` 就只写那一个人的表，外加汇总表和合并表。想完全不动正式产物，用 `ymtc_config.m` 把 `outDir` 指到临时目录。
