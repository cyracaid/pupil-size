# 07 · 审阅路径（中文）

EN: The order to read the upstream code and our own in, what to look at in each file, and where the statistics live.
KO: 업스트림 코드와 우리 코드를 어떤 순서로 읽고, 각 파일에서 무엇을 보고, 통계가 어디 있는지.
ZH: 上游代码和我们自己的代码按什么顺序读、每个文件看什么、统计在哪里。

这一页是**审阅**用的。什么做完了、下一步做什么，是另一页：[08 · 路线图与待办](08_待办.md)。

为什么要讲顺序：这个仓库是两个代码库在一个接缝上粘起来的。上游决定"什么算有效样本"，
我们这层决定"什么算一个 marker"。按**数据流**读，不要按文件夹读，后面遇到的每个数字才有出处。

## 0 · 先建坐标系（10 分钟）

1. [01](01_流程总览.md) —— 五层结构，先知道自己在看哪一层；
2. [02](02_列字典.md) §A–§H —— 八张表和它们的列，扫一遍，不用背；
3. `code/ymtc/README.md` —— 我们这层的调用链，一屏。

做完这一步，你应该能不看代码就说出 `06_merged/06_all_merged.csv` 里某个数字从哪来。

## 1 · 上游：四个函数就是全部（45–60 分钟）

按这个顺序读，后一个只有在前一个读完之后才讲得通。

| # | 文件 | 读什么 | 你在核对什么 |
|---|---|---|---|
| 1 | `code/helperFunctions/rawDataFilter.m` | `getDefaultSettings`，然后 `removeOutOfBounds` → `madSpeedFilter` → `expandGaps` → `madDeviationFilter` → `removeLoners` | **这个文件决定什么算有效样本。**看五个阈值、看每个是不是 `median + n·MAD`（不是均值±SD）、看 `isValid` 是否只会被收紧不会被放宽 |
| 2 | `code/dataModels/ValidSamplesModel.m` | `interpAndSmooth` | 1000 Hz 网格、4 阶 Butterworth 4 Hz + `filtfilt`、以及把超过 `interp_maxGap` 的缺口重新变回 NaN 的那一步。"曲线很平滑但均值是编出来的"就来自这里 |
| 3 | 同一个文件 | `analyze` + `getDefaultSettings` | 每段 12 个统计量 —— 见下面 §4 |
| 4 | `code/dataModels/PupilDataModel.m` | `filterRawData` → `processValidSamples` → `analyzeSegments` → `exportSegments` | 批处理循环，以及 `04_all_segments.csv` 的列布局；`analyzeSegments` 是唯一遍历"段 × 被试"的地方 |

略读：`RawSamplesModel.m`、`RawFileModel.m`（mat 文件结构与 `segmentData`）、`plotData`
（桌面 MATLAB 里的人工检查）、`helperFunctions/plotSegments.m`。

可以直接跳过：`helperFunctions/FALLBACK/` 与 `LEGACY/`（老版本 MATLAB 的兼容层）、
`importEDF/`（Windows mex）、`code/Examples/`（Eyelink 与 Tobii 的演示，都不是 YMTC 这条路）。

## 2 · 我们这层：三段，按数据顺序（30 分钟）

| # | 文件 | 读什么 | 你在核对什么 |
|---|---|---|---|
| 1 | `code/ymtc/trk2csv.m` | 整个文件，然后 `private/readTrk.m` → `private/labelSamples.m` → `private/checkTrk.m` | 一样本一行；事件挂在**时间戳 ≥ 事件时刻的第一个样本**上（最多晚约 17 ms）；`run` 只数 `START`，所以缺第一个 `START` 就是 run 0；不修补，只记录 |
| 2 | `code/ymtc/exportEvents.m` | 整个文件 | 同一批事件，但用事件自己的时刻 —— 这是 marker 表的输入，也是 `diff_s` 不被采样网格带偏的原因 |
| 3 | `code/ymtc/ymtcEventTable.m` | 先看文件末尾的 `readOrder`，再看主循环 | order 怎么选（按倒计时长度匹配）、`condition` 从哪来（`Onset<cond>`）、`expected_*` 与 `diff_s` 的定义、以及 `run = ceil(trial/21)` 为什么需要 `ymtcRunCheck` 兜底 |
| 4 | `ymtcEventTableBatch.m` | 只看结构 | 每个被试的状态；`skipped_no_events` 是正常结果，不是错误 |
| 5 | `ymtcRunCheck.m`、`ymtcTimingCheck.m`、`ymtcTrialWide.m` | 只看判定那几行 | 三个独立检查；任一个是绿的，它守的那个前提就成立 |

## 3 · 两个代码库的接缝（20 分钟）

只有三条**约定**，而它们正好是审阅最容易出错的地方：

1. **四个段的定义**在 `csv2kretmat.m` 里，而它**不在本仓库**（见 [04](04_我们的代码.md)）。在读到那个文件之前，
   `countdown_SmoothSig_meanDiam` 只是一个未经核对的声明，不是定义；
2. **连接键**是 `participant` + `run` + `trial`；合并表的行语义是"某段的统计落在该段起始 marker 那一行"，
   而 run 级行根本没有 `trial`（[02](02_列字典.md) §H）；
3. **单位是相机像素，不是毫米**。论文的 range filter（1.5–9）是毫米，被数据驱动的像素范围覆盖了；
   拿这里的直径去和文献里的 mm 值比是没有意义的（[03](03_瞳孔算法.md)）。

## 4 · 统计在哪里

按一个数字被碰到的顺序，有五个地方：

| # | 位置 | 算什么 | 在本仓库？ |
|---|---|---|---|
| 1 | `rawDataFilter.m` —— `madCalc`、`deviationCalculator` | 中位数与 MAD，以及偏差滤波要对比的趋势线 | 是 |
| 2 | `ValidSamplesModel.analyze` | 每段 12 个统计量：`SmoothSig_{mean,min,max,missingDataPercent,sampleCount}`、`ValidSamples_{mean,min,max,validPercent,sampleCount}`，加 `segmentStart/End` | 是 |
| 3 | `PupilDataModel.analyzeSegments` / `exportSegments` | 遍历段并写出；自己没有算术 | 是 |
| 4 | `ymtcTrialQC.m`（数据侧） | 分析方案的三条剔除规则 —— [05](05_数据质量.md) 的 R1/R2/R3 | **否** |
| 5 | 实验室的统计脚本（Fretz） | 推断层：最终进图、进检验的那些数 | **否** —— 确认入口后把路径补到这一行 |

统计上有两个坑，它们属于统计、不属于滤波器：

- `ValidSamples_validPercent` 是**整段记录**口径，重复出现在每一行；段内缺失比例要看 `SmoothSig_missingDataPercent`；
- `min` / `max` 是单样本统计量：只要有一个伪影漏过来，它们就变。看均值时必须同时看
  `SmoothSig_missingDataPercent` 与 `ValidSamples_sampleCount`。

想手算核对一个数：从 `04_all_segments.csv` 取一行，按 [02](02_列字典.md) §B 的窗口取出平滑信号
（`segments/<name>_leftpupil_segments.csv`），重算均值。如果你算的和表里不一样，去查
`csv2kretmat.m` 里的段边界。

## 5 · 一个下午能走完的审阅流程

| 步骤 | 时间 | 什么算走完 |
|---|---|---|
| 0 · 坐标系（§0） | 10 分钟 | 能说出八张输出表各自的角色 |
| 1 · 上游（§1） | 45–60 分钟 | 能画出 原始 → 有效 → 平滑 → 分段，并说出每个箭头对应哪个文件 |
| 2 · 我们这层（§2） | 30 分钟 | 能不打开文件就把一个 marker 行的来龙去脉说完 |
| 3 · 接缝（§3） | 20 分钟 | 手上有了三个要问数据侧的问题 |
| 4 · 统计（§4） | 20 分钟 | 知道 12 个统计量里哪些是段内口径、哪个是整段记录口径 |
| 5 · 抽样复算 | 20 分钟 | 手算复现了一张表里的一个单元格，而且故意挑的是有缺失的行 |

有五个问题越早问越好，因为在这里读多少代码都答不了：四个段的定义到底是什么；用的像素范围是多少、
为什么；合并时保不保留 run 级行；分析侧哪些脚本已经定稿；以及 Fretz 的统计脚本在哪。
