# 04 · 我们自己的代码，以及什么放在哪儿（中文）

## 在这个仓库里 —— `code/ymtc/`

| 文件 | 作用 |
|---|---|
| `trk2csv.m` / `trk2csv_batch.m` | `.trk` → 每人一个 CSV；异常只记录，不修补 |
| `private/readTrk.m`、`labelSamples.m`、`checkTrk.m` | 解析、把事件挂到样本上、与任务应有状态对比 |
| `ymtcEventTable.m` / `ymtcEventTableBatch.m` | 每 marker 一行，按任务顺序；条件从 marker 名读出 |
| `ymtcRunCheck.m` | 每个 run 是不是真的 21 个 trial（用 BurnInStart 数） |
| `ymtcTimingCheck.m` / `ymtcTrialWide.m` | `diff_s` 的描述统计；长表 → 一 trial 一行 |
| `ymtcConfig.m` / `ymtc_config.template.m` | 文件夹在哪；代码里不写路径 |
| `checkDocs.m` | 列字典 vs 真实表头 |

调用链和阅读顺序见 [`code/ymtc/README.md`](../code/ymtc/README.md)。上面这些全部只用 base MATLAB，不需要任何工具箱。

## 不在这个仓库里 —— 分析层

这些文件和研究数据放在一起（要读被试文件夹和 Kret 的 `.mat`），所以没有随仓库发布：

| 文件 | 作用 |
|---|---|
| `csv2kretmat.m` | 逐样本 CSV → Kret 格式 `.mat`，并定义每个 trial 的四个段 |
| `example_kret_pipeline.m` | 跑 pupil-size 模型：滤波 → 插值 → 分段 → 统计 → QC → 导出 |
| `ymtcTrialQC.m` | 分析方案的三条剔除规则 |
| `ymtcMergeResults.m` | 事件行 + 四个段 → `06_合并表/06_all_merged.csv`（69 列） |
| `ymtcManipulationCheck.m`、`ymtcLayer1Bins.m`、`ymtc_param_sensitivity.m` | 分析用脚本，不属于数据管线 |

要用它们就得连同数据一起，因为它们编码了这项研究的目录结构和分析决定。

## 两层靠什么对上

只有两条约定，而且都写在文档里：

1. **四个段的定义**（在 `csv2kretmat.m` 里）——`countdown_SmoothSig_meanDiam` 这类列能不能跨层比较，全靠它；
2. **`participant` + `run` + `trial`**——`ymtcMergeResults.m` 的合并键。

这两条任意一条变了，合并出来的表就不再是列字典描述的那张表，而且不会报错。
