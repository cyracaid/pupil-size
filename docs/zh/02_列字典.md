## A. 事件表（18 列）

一行一个 marker。5 步版每个 trial 4–5 行；完整版多出 `WhiteNoise_part2-4`。

| 列 | 含义 | 怎么算 | 单位 |
|---|---|---|---|
| `participant` | 被试编号 | 取自文件名 | – |
| `order` | 该被试实际跑的是第几套序列（1–5） | 用倒计时时长与 `TrialOrder1-5Run1-4.xlsx` 比对选出 | – |
| `run` | run 编号 1–4 | `ceil(trial / 21)`，由 `ymtcRunCheck` 验证 | – |
| `trial` | 被试内 trial 编号 1–84 | `CueStart` 事件的计数 | – |
| `trial_in_run` | run 内的序号 1–21 | `trial - (run-1)*21` | – |
| `ymtc_marker` | 任务自己的 marker 名，如 `OnsetPTCTO`、`Rating` | 从 order 工作簿读 | – |
| `trk_event` | 与之匹配的 trk 事件名 | 固定映射，见 §H | – |
| `time_ms` | 眼动仪原始时间戳 | 原样拷贝 | ms |
| `t_from_onset_s` | 相对本 trial Onset 的秒数 | `(time_ms - onset_ms)/1000` | s |
| `expected_from_onset_s` | 设计上这个 marker 应该在哪 | order 工作簿的 `onsets` | s |
| `diff_s` | 实测减设计 | `t_from_onset_s - expected_from_onset_s` | s |
| `expected_duration_s` | 这个 marker 设计上持续多久 | order 工作簿的 `durations` | s |
| `condition` | 条件码 `PTCT` `PTCS` `PTUO` `UTCT` `UTCS` `UTUO` | `Onset` 之后的前 4 个字符 | – |
| `timing` | 时间可预测 / 不可预测 | `condition(1)`：`P` / `U` | – |
| `certainty` | 结果在 cue 时是否已知 | `condition(3)`：`C` / `U` | – |
| `outcome` | **cue 宣告的**结果 | `condition(4)`：`T` / `S` / `O`（`O` = 没宣告） | – |
| `actual_outcome` | 这个 trial **实际**落在什么结果上 | `T` / `S`；确定条件等于 `outcome`，不确定条件看 `OutcomePTUOT` / `OutcomePTUOS` | – |
| `step` | 在 trial 里的位置 | 1 Onset、2 倒计时开始、3 Outcome、4 WhiteNoise、5 Rating | – |

`outcome` 里的 `O` 是最容易误读的一列：两个“结果不确定”的条件，cue 时不可能知道是威胁还是安全，所以 `outcome` 是 `O`，只有 `actual_outcome` 才给出最终结果。

## B. 段统计（12 个概念 × 4 个前缀）

任何形如 `<段>_<统计>` 的列，`<段>` 是 `baseline` / `countdown` / `preOutcome` / `postOutcome`。四段的窗口（相对 Onset，单位秒）：

| 段 | 窗口 | 用途 |
|---|---|---|
| `baseline` | `[Onset − 0.5, Onset)` | cue 前基线，做基线校正用 |
| `countdown` | `[Onset, Outcome)` | 等待期，主分析窗 |
| `preOutcome` | `[Outcome − 2.0, Outcome)` | 结果前 2 s，GLM 调节量 |
| `postOutcome` | `[Outcome, Outcome + 2.0)` | 结果后的反应窗 |

同一段有两套统计，来自两条不同的信号：

- **`SmoothSig_*`**：插值 + 滤波后的连续信号。有效样本线性插值到 1000 Hz，再走 4 阶 Butterworth 低通（4 Hz，零相位 `filtfilt`）。超过 250 ms 的缺口不插值，保持 missing。
- **`ValidSamples_*`**：只算通过三道伪影滤波的真实样本，不插值、不平滑。

| 统计 | 含义 | 怎么算 | 单位 |
|---|---|---|---|
| `segmentStart` / `segmentEnd` | 段的起止 | 从记录开始算的秒数（第一个样本 = 0） | s |
| `SmoothSig_meanDiam` | 该段平滑信号的平均直径 | 段内均值 | px |
| `SmoothSig_minDiam` / `maxDiam` | 平滑信号的最小 / 最大 | 段内极值 | px |
| `SmoothSig_missingDataPercent` | 该段缺失比例 | 缺失样本 / 段内样本 | % |
| `SmoothSig_sampleCount` | 段内样本数 | 1000 Hz 下约等于段长 × 1000 | 个 |
| `ValidSamples_meanDiam` | 真实样本的平均直径 | 段内有效样本均值 | px |
| `ValidSamples_minDiam` / `maxDiam` | 真实样本的极值 | 段内极值 | px |
| `ValidSamples_validPercent` | **整段记录**的有效比例 | 这只眼全程有效样本 / 全程样本 | % |
| `ValidSamples_sampleCount` | 段内有效样本数 | 计数 | 个 |

三个最容易踩的坑：

1. `ValidSamples_validPercent` **不是这一段的**，是整段记录的一个数，同一被试每行都一样。要看这一段缺多少，用 `SmoothSig_missingDataPercent`。
2. `SmoothSig_meanDiam` 含插值补出来的点。100 ms 的缺口会被填平、看起来完全正常；只有超过 250 ms 才变成 missing。所以它必须和 `missingDataPercent` 一起看。
3. 单位是**相机像素**，不是毫米。Range filter 的上下限由数据定（0.5–99.5 百分位 × 0.8 / 1.2），不是论文的 1.5–9 mm。

## C. 质控列

| 列 | 出现在 | 含义 | 规则 |
|---|---|---|---|
| `RejectCountdown` | `04_all_trials_qc.csv`、最终表 | 这个 trial 被剔除 | countdown 段缺失 > 50% |
| `PreOutcomeMostlyMissing` | 同上 | 只是标记，trial 保留 | preOutcome 段缺失 > 50% |
| `SubjectExcluded` | 同上 | 整个被试被排除 | 该被试被剔 trial 超过 20% |
| `nTrials` / `nRejected` / `rejectPct` | `04_all_subjects_qc.csv` | 被试级计数与比例 | 由上面三条推出 |

## D. `04_all_segments.csv`（16 列）

一行 = 一个被试 × 一个 trial × 一个段（每 trial 4 行）。前 6 列是段的身份，后 10 列是 §B 的统计（无前缀）。

| 列 | 含义 |
|---|---|
| `segmentStart` / `segmentEnd` | 段的起止（秒，从记录开始） |
| `segmentName` | 如 `countdown_004` = 第 4 个 trial 的 countdown 段 |
| `segmentType` | `baseline` / `countdown` / `preOutcome` / `postOutcome` |
| `participant` / `trial` | 被试、trial 编号 1–84 |
| 十个 `leftPupil_*` | 见 §B |

## E. `05_all_trials_wide.csv`（14 列）

一行一个 trial，把长表压成一行。

| 列 | 含义 | 单位 |
|---|---|---|
| `participant`、`order`、`run`、`trial` | 身份 | – |
| `condition`、`timing`、`certainty`、`outcome` | 同 §A | – |
| `onset_s` | 恒为 0，参照点 | s |
| `countdown_s` | 倒计时开始（cue 结束） | s |
| `outcome_s` | 结果出现 | s |
| `whitenoise_s` | 白噪声开始 | s |
| `rating_s` | 评分开始；该 trial 无评分时为 NaN | s |
| `has_rating` | 这个 trial 有没有评分（84 个里 24 个有） | 逻辑 |

## F. `05_all_timing_check.csv`（7 列）

一行 = 一个被试 × 一个 marker。

| 列 | 含义 |
|---|---|
| `participant` | 被试 |
| `phase` | `1 Onset` … `5 Rating start` |
| `n` | 该格里的 marker 数 |
| `mean_s` / `sd_s` | `diff_s` 的均值与标准差 |
| `min_s` / `max_s` | `diff_s` 的极值 |

## G. `07_all_run_check.csv`（9 列）

一行一个被试，用来守住 `run = ceil(trial/21)` 这个前提。

| 列 | 含义 |
|---|---|
| `participant`、`status` | 编号；`ok` / `no_file` / `no_events` |
| `nSTART`、`nBurnInStart`、`nBurnOutStart`、`nCueStart` | 各类事件的数量 |
| `trialsPerRun` | 如 `21/21/21/21`，用 BurnInStart 做分界数出来的 |
| `runAssignmentOK` | 每个 run 都是 21 个 trial 且计数一致时为 true |
| `note` | 用人话说明哪里不对 |

## H. 合并后的最终表 `06_merged/06_all_merged.csv`（69 列）

一行一个 marker，把四个段的瞳孔统计挂在同一行：

```
18 个事件列（§A） + 4 个段 × 12 个统计（§B） + 3 个质控列（§C） = 69
```

段列就是 §B 的名字加段前缀，例如 `countdown_SmoothSig_meanDiam`、`preOutcome_ValidSamples_sampleCount`。

## I. marker ↔ trk 事件对照

| trk 事件 | 对应步骤 | 说明 |
|---|---|---|
| `CueStart` | 1 Onset | cue 出现，设计 1 s |
| `CueFinish` | 2 倒计时开始 | cue 消失 |
| `StimuliStart` | 3 Outcome | 结果呈现，设计 2.7 s |
| `WhitenoiseStart1` | 4 WhiteNoise | 2–4 是同一段噪声的后续标记 |
| `RatingStart` | 5 Rating | 84 个 trial 里 24 个有 |
| `START` / `BurnInStart` / `BurnOutStart` | – | run 级，无 trial、无条件 |
| `CountdownFinish` | – | 倒计时数字跳变，不是 marker |
